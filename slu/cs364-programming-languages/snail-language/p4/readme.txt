# Project 4 : Parser

This project is a parser for the Snail programming language, implemented in Python using PLY.
The parser processes tokens generated by the lexer and constructs an Abstract Syntax Tree (AST) based on the
defined context-free grammar.

## Key Components

### parser.py
The main parser implementation that:
- Defines the grammar rules for the Snail language
- Constructs the Abstract Syntax Tree (AST)
- Implements error handling for invalid syntax
- Handles operator precedence and associativity
- Processes different types of expressions (arithmetic, control flow, method calls, etc.)
- Validates class names and inheritance rules

Key features:
- Support for class definitions and inheritance
- Method and member variable declarations
- Expression handling (arithmetic, boolean, control flow)
- Array operations
- Method dispatch (static and dynamic)
- Error reporting with line and column information

### token_reader.py
A specialized token reader that:
- Reads SL-LEX formatted tokens from input
- Maintains line and column information for error reporting
- Provides an iterator interface for token processing
- Handles different token types (identifiers, strings, integers, etc.)

The TokenReader class works as an adapter between the SL-LEX format and PLY's parser requirements.

## Input Format
The parser takes as input a list of tokens produced by the Snail lexer.

## Output Format
The parser outputs an AST representing the syntactic structure of the input program.
The AST is constructed as a nested dictionary containing details like class names, methods, members, and expressions.

## Testing

In our **test-1-class** file we mostly tested the parser's handling of classes. We tested for:
    1. Recognizing forbidden class names
    2. Recognizing forbidden inheritance class names
    3. Not mixing up the list of forbidden class names with the list of forbidden inheritance class names
    4. If it makes sure it's case sensitive
    5. If it returns the right value output for strings with leading spaces

In the **test-2-precedence** file we tested all the precedence and associativity rules.

In **test-3-bad** we tested if it handles forbidden method and member names correctly.

## About the code

### Grammar Rules

1. **Program and Classes**:
   - The program consists of one or more classes
   - Each class can (optionally) inherit from another class
   - Classes can contain features such as methods and member variables

2. **Features**:
   - Member variables can be declared with or without an initial value
   - Methods can have parameters and a body consisting of a block of expressions

3. **Expressions**:
   - Supports literals (integers, booleans, strings), identifiers, arithmetic operations, and blocks of expressions

## Error Handling
The parser provides detailed error messages including:
- Line and column numbers for error locations
- Specific error descriptions for invalid syntax
- Validation errors for restricted names and operations
- Empty method body detection
- Invalid inheritance checks
